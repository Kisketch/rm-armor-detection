本机 Linux、GCC 15.2、OpenCV 4.10、Release 构建。两段原片均完整重新检测，再从带来源签名的缓存回放。缓存回放的基本报告与完整重检一致。以下命令中的 `<video-dir>` 为包含 `3.avi` 和 `4.avi` 的目录：

```bash
cmake -S autoaim -B autoaim/build -DCMAKE_BUILD_TYPE=Release
cmake --build autoaim/build -j4
ctest --test-dir autoaim/build --output-on-failure
./autoaim/build/autoaim_video <video-dir>/3.avi --out autoaim/out --redetect
./autoaim/build/autoaim_video <video-dir>/4.avi --out autoaim/out --redetect
python3 autoaim/tools/regression.py --exe autoaim/build/autoaim_video \
  --video-dir <video-dir> --out autoaim/out
```

同步来的回归脚本原本只按独立仓库的相对路径找视频；现已支持 `--video-dir`，并自动识别统一仓库旁边的素材目录。当前复跑六项视频指标全部与冻结基线相同，仿真八场景均值 77.8%，与脚本参考值 78.1% 相差 0.3 个百分点，通过现有 3 个百分点的跨环境容差。仿真不能替代真实视频或实车验证。

CI 也改为在同一个 Ubuntu 任务中先检查作业，再共用已安装的 OpenCV 构建和测试 `autoaim/`。原先两个并行任务分别下载约 205 MB 的相同依赖；本轮远端自瞄任务两次停留在系统包下载阶段，合并任务是为减少重复下载及其不稳定性，测试内容仍保留。

## 新增：相同射速上限的对照

对每个策略的已记录射击采用“从第一发开始，间隔满足上限才保留下一发”的规则。25 fps 只允许逐帧作决策，所以 10、15 发/秒是**上限**，实际可实现的最短帧间隔分别是 3、2 帧。表中的命中/全部发射把无法判定的射击也计入分母。下表只列直接瞄准与整车 EKF；完整逐项见报告。

| 原片 | 上限 发/秒 | 直接瞄准 发/中/命中每秒 | 整车 EKF 发/中/命中每秒 |
| --- | ---: | --- | --- |
| 3.avi | 5 | 423 / 136 / 1.5 | **350 / 228 / 2.6** |
| 3.avi | 10 | 692 / 228 / 2.6 | **547 / 349 / 3.9** |
| 3.avi | 15 | 1019 / 338 / 3.8 | **776 / 495 / 5.6** |
| 4.avi | 5 | 668 / 374 / 2.7 | **616 / 426 / 3.1** |
| 4.avi | 10 | 1078 / 602 / 4.4 | 848 / 596 / 4.4 |
| 4.avi | 15 | **1570 / 846 / 6.2** | 1218 / 815 / 6.0 |

这解释了为何未限速的 4 号视频直接瞄准能达到 11.8 命中/秒，而整车 EKF 为 10.0：直接瞄准会发更多弹。5 发/秒上限时 EKF 在两段视频均占优；15 发/秒上限时 4 号仍是直接瞄准略多命中。**没有实测射速、热量与弹量规则之前，不据此自动切换实车策略。**单元测试覆盖 5／10／25 发/秒、离散帧间隔和未知射击保留。

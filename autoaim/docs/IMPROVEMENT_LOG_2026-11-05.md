## 观看结论与找到的错误

1. 全片 `06`、`07`、`08` 的左右栏逐帧对齐。抽查 3 号第 0/850/2208 帧和 4 号第 0/2625/3415 帧，左栏与相应原片在同样 gamma/缩放后的平均像素差约 1.5–1.7，主要是 MP4 压缩。
2. 原短片 `01`、`02` 及拼接的 `03` **不对齐**：生成器给右栏叠加视频使用 850/2625 起始帧，却让左栏从原片第 0 帧开始。原 `01` 第一帧对真实第 0 帧的平均差为 1.54，对标注的第 850 帧则为 9.71；原 `02` 对第 0 帧为 1.55，对第 2625 帧为 3.47。短片此前不能用来判断同一时刻的瞄点是否正确。
3. 修复后重新生成两个 151 帧短片和 12 秒合集。新短片首、中、末帧对正确原帧的平均像素差约 1.9；错误合集保留为 `compare_3and4_unaligned_legacy.mp4`，不要再用它评估算法。仓库当前 `compare_3and4.mp4` 是对齐版；共享目录里的原始包未覆盖。
4. 抽看灯条三栏和对齐的全片：`R−B` 掩膜在这些红色目标上能抑制大量背景，绿框多数落在可见装甲板；遮挡、快速切板与远距离小目标仍明显困难。关键帧 `*.png` 展示的是灯条/掩膜，不是自瞄精度真值。
5. 两段被重点展示的 151 帧难例，当前版本 3 号有 39 帧 `TEMP_LOST`、60 发虚拟射击仅 19 中/33 未中/8 无法判定（可判定命中率 36.5%）；4 号有 12 帧 `TEMP_LOST`、94 发中 52/未中 42（55.3%）。这比全片平均差，后续应专门评测丢失恢复和遮挡。

## 本次代码变更

### 1. 选板状态只在最终瞄准结果确定后提交

`RobotAimer` 原先在一次瞄准的每轮飞行时间迭代中都写入 `last_armor_`，使本轮临时结果充当“上一帧选板”；目标丢失或换 ID 时也没有清掉旧板索引。现在每轮都相对上一帧的选板做滞回比较，四轮结束才提交最终索引；失去跟踪或换目标时清空。新增合成重捕获测试，避免旧索引影响新目标。

在**同一份旧检测缓存**上隔离比较该改动，预测误差及跟踪状态不变：

| 视频 | `a0c655b`：发数 / 命中 / 可判命中率 / 命中每秒 | 本次选板修正：发数 / 命中 / 可判命中率 / 命中每秒 |
| --- | --- | --- |
| 3.avi | 1394 / 901 / 67.2% / 10.20 | 1408 / 906 / 66.9% / 10.25 |
| 4.avi | 1956 / 1303 / 68.1% / 9.54 | 2019 / 1327 / 67.2% / 9.71 |

**取舍：**每秒虚拟命中数略增，射击次数也增加，条件命中率下降 0.3/0.9 个百分点。若电控有发射热量或弹量约束，需用真实规则和实测云台响应决定是否保留 3° 滞回与当前开火窗口，不能只按命中每秒选参数。

### 2. 检测缓存绑定原视频与检测配置

旧版缓存仅按视频文件名和帧数复用。同名、同帧数的另一段视频或修改 `refine_corners` 后会悄悄读入旧检测，污染调参和报告。现在用完整视频内容、模型、标签、全部检测参数及 OpenCV 版本生成缓存指纹；旧/不匹配/损坏缓存自动重新检测。`--sweep refine_corners` 会报错并提示分开运行，因为该参数必须重做检测。

缓存坐标从三位小数改为可往返恢复浮点数的精度。原来读缓存会改变极少数擦边射击的判定；现在对两段原片各自先完整重检、再读缓存，生成的报告和逐帧 CSV **逐字节一致**。缓存只服务离线分析，不是实车采集链路。

### 3. 对比视频生成器可复现

`make_compare_video.py` 现在先将原片寻到叠加片段的起始帧，并验证帧数；去掉硬编码的 Windows 用户目录与 ffmpeg 路径，支持 `--video-dir`、`--overlay-dir`、`--out-dir`、`--ffmpeg`。加入合成视频对齐测试。全片版本保持原内容不变。

### 4. 未采用的试验

尝试按归一化 yaw 创新自适应增大 yaw 过程噪声，上限从 1 扫到 16：3 号仍为 67.2%，4 号从 68.1% 降到 67.7%。没有稳定收益，代码已撤回。旧文档中“误差已到信息极限”的判断来自虚拟评测；在真实标定与独立标注前不把它当作物理上限。

## 下一步建议（按依赖顺序）

| 优先级 | 动向 | 要准备的资料 | 可检查的完成标准 |
| --- | --- | --- | --- |
| P0 | 真相机标定与位姿验证 | 实际相机、镜头、焦距/对焦状态、采集分辨率；平整的 9×6 **内角点**棋盘格，实测方格边长；20–30 张覆盖四角和倾角的照片 | `calibrate_camera.py` 输出真正的 `camera.yml`；检查每张重投影误差与覆盖，目标总 RMS <0.5 px、最大单张 <1 px；再用独立测量的 2/4/6 m 靶位核对 PnP 距离和角度。通过前保持 draft PR，不合并 |
| P0 | 台架闭环与时间链路 | 相机硬件时间戳、相机到云台外参、IMU 姿态/时间戳、MCU 串口字段/单位/校验、云台阶跃响应、实测弹速与总延迟 | 首先做无弹闭环：每帧记录采集时刻、估计、命令、执行反馈；测出延迟分布和外参误差，再替换 60 ms/30 ms/25 m/s 的假设值 |
| P1 | 独立标注与难例集 | 从 3/4 号的换向、切板、`TEMP_LOST`、近远距离各抽样；补蓝灯和其它数字/兵种/场地 | 标出灯条/装甲板四点、ID、可见性及机器人轨迹；报告 precision、recall、角点误差、位姿误差、丢失恢复时长。训练、调参和最终评估使用不同片段 |
| P1 | 丢失恢复与快速横移 | 上述标注，加 ≥100 fps 或里程计/IMU 的新序列 | 在固定误报率下减少难例的 `TEMP_LOST` 和恢复延迟；尤其验证硬平移仿真（现有无旋转横移约 18%）及真数据，不因提高全片虚拟命中率牺牲安全开火判断 |
| P2 | 模型检测与部署 | 多类别标注、可用 GPU、目标设备及功耗/帧率预算 | 按 `yolo_keypoints_plan.md` 做关键点模型与传统检测器对照，含蓝/红、遮挡、角点、延迟和功耗；之后才考虑 ROS 2/能量机关等新功能 |

以上顺序反映本次素材能证明的范围：当前离线链路可复现，硬件参数和独立真值尚缺，不能把视频里的虚拟 FIRE/HIT 直接搬到实车。

# 待办池（用户确认"后期再做"的两项）

> 建立于 2026-11-05。这里只记录**已定方案、已量化收益、缺外部条件**的事项；
> 视觉侧自己就能做的改动不放这里（直接进分支）。

## B-01 云台速度前馈（需要电控配合）

| 项 | 内容 |
| --- | --- |
| 现状 | 视觉每帧下发 yaw/pitch 角度；云台按一阶滞后跟随（τ≈30 ms，限速 12 rad/s） |
| 仿真证据 | `gimbal_ff` 从 0 → 1.0：硬平移场景 43.8% → **51.1%**，整体均值 78.0% → 79.2%；ff=0.5 时无旋转硬平移 14.4% → 18.0% |
| 需要 | 电控在接收角度的同时接收 **yaw rate**（或云台控制器内部做速度前馈）；视觉侧愿意按固定频率发 `yaw, yaw_rate, pitch, pitch_rate` |
| 验收 | 仿真 `gimbal_ff=1` 的收益在实车复现 ≥ 5 pp（硬平移场景），且不影响稳态精度 |
| 备注 | 这是评测参数，默认 0；不改默认值就不会污染交付数字 |

## B-02 YOLO 关键点检测（需要 GPU + 数据集账号）

| 项 | 内容 |
| --- | --- |
| 方案 | 见 `docs/yolo_keypoints_plan.md`（YOLO11n-pose，4 关键点，ONNX → OpenCV DNN） |
| 数据 | Roboflow ARUW 18 557 张（4 关键点）、Sam 23 282 张（检测框）；需 Roboflow 账号/API key |
| 算力 | GPU 约 13 GPU·h；本机 CPU ≈ 770 CPU·h（不可行）；VM 无 GPU |
| 验收 | 侧对召回 ≥ 传统 1.3×、关键点中位误差 ≤ 3 px、CPU ≤ 15 ms/帧、3.avi/4.avi 命中率不低于当前基准 |
| 阻塞 | ① GPU 机器；② 数据集下载权限。两者任一到位即可开工 |

## B-03 IMM（交互多模型）

- 目前不做。CA（常加速）已在 25 fps 数据上验证失败（真实视频 −5~−7 pp），说明**加速度不可观测**是瓶颈，换 IMM 不会改变这一点。
- 触发条件：相机换到 ≥100 fps，或引入 IMU/轮式里程计提供自身运动补偿后再评估。
